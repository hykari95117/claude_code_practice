# Shift+Tab (Plan ↔ Accept)
- `Shift + Tab` : Plan Mode ↔ Accept Mode 전환
- Plan Mode : Claude가 계획만 세우고 실행은 하지 않는다.(코드 바로 생성 X)
- Accept Mode : Claude가 계획 + 실행까지 수행(Claude에게 write 권한을 준다.)
- 새로운 작업은 항상 Plan Mode로 시작, 계획을 확인한 후 Accept Mode로 전환하면 엉뚱한 수정을 예방할 수 있다.
### Plan Mode를 사용해야 하는 실무적 이유
#### 1. 토큰 최적화
##### 불필요한 코드 생성 방지
- 바로 코딩에 들어가면 방향이 틀렸을 때 생성된 코드 전체가 낭비 토큰이 된다.
- Plan Mode에서 방향을 먼저 확인하면 `잘못된 코드 생성 → 수정 요청 → 재생성`의 비효율 방지
##### 컨텍스트 윈도우 보존
- Claude Code는 대화가 길어질수록 이전 컨텍스트를 압축하거나 날린다.
- Plan Mode로 짧은 텍스트 기반 계획을 먼저 세우면 실제 코딩 단계에서 컨텍스트 윈도우를 온전히 코드 생성에 쓸 수 있다.

#### 2. 실행 정확도 향상
##### 복잡한 테스트 분해
- `이 기능 만들어줘`라고 바로 던지면 Claude가 한 번에 모든 걸 해결하려다 중간에 길을 잃는다.
- Plan Mode에서 Step 1,2,3로 나누고 각 단계를 승인하면서 진행하면 실패율이 크게 줄어든다.
##### 파일 수정 범위 통제
- Plan 없이 실행하면 의도치 않은 파일까지 건드리는 경우가 많다.
- 계획 단계에서 `어떤 파일을 어떻게 수정할 건지` 미리 확인하면 side effect를 줄일 수 있다.

#### 3. 비용 관리(API 사용 시)
- Opus 기준 input/output 토큰 단가가 비싸다.
- Plan Mode에서 계획을 세울 때는 output이 주로 텍스트 계획이라 토큰 소모가 적고 잘못된 방향으로 수천 줄 코드를 생성하는 것보다 비용 효율이 훨씬 좋다.

#### 4. 실무 워크플로우 TIP
- `Plan → 검토 → Execute` 패턴을 습관화
    1. `/plan` 모드에서 요구사항 전달
    2. Claude가 제시한 계획 검토 및 수정 요청
    3. 계획 확정 후 실행 모드로 전환하여 코딩

# Escape 중단 & 복원(Esc key)
- Esc 1번 : 즉시 중단
- Esc 2번 : 입력 삭제 / 복원
    - 입력창에 내용이 있을 때 → 입력 내용 삭제
    - 입력창에 내용이 비어있을 때 → 이전 입력 복원

# 스크린샷 드래그 앤 드롭
- 터미널에 스크린샷을 드래그하면 Claude가 이미지를 인식한다.
- 이미지와 함께 `무엇인지 + 어떻게 할 것인지`를 같이 명령

# ! 접두사 bash 실행
- Claude Code 프롬프트에서 `!`를 붙이면 대화를 끊지 않고 터미널 명령어를 바로 실행할 수 있다.
```
ex)
!npm run build
!git status
!ls -la src/
```
