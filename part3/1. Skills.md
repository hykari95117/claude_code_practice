# 스킬 (Skills)
- 반복되는 작업을 재사용 가능한 skill로 정의

## Skills란?
- 반복되는 프롬프트를 `SKILL.md` 파일에 정의하여 AI에게 <u>**업무 메뉴얼**</u>처럼 전달하는 기능
- 한 번 만들면 자동 트리거 or `/skill-name`으로 호출하여 매번 같은 품질의 결과를 얻을 수 있다.<br>
- cf) Claude Code skills는 Agent Skills라는 공개 표준을 따른다. = Claude Code에서만 쓸 수 있는게 아니라 다른 AI 도구에서도 쓸 수 있는 범용 규격

#### 프롬프트 vs Skills 비교
- `프롬프트` : 매번 입력, 결과 들쭉날쭉, 공유 어려움
- `Skills` : 한 번 만들면 자동 호출, 품질 일관, 팀 공유 가능
- `프롬프트`가 <u>한 번의 지시</u>라면 `Skills`는 <u>재사용 가능한 업무 시스템</u>

#### Skills를 쓰는 3가지 이유
- 반복 자동화 : 같은 프롬프트를 매번 입력하지 않아도 됨, ex) `/ppt`만 치면 끝
- 품질 일관성 : 순서, 형식, 체크리스트가 정해져 있어 누가 실행하든 같은 기준
- 팀 공유 : Git에 올려서 팀원과 공유하면 팀 전체가 같은 자동화 사용(팀 전체가 같은 워크플로우)

## 스킬 구조와 로딩 방식
```md
ex)
.claude/skills/
└── ppt-generator/      ← 스킬 폴더
    ├── SKILL.md        ← 핵심 파일 (필수), 진입점
    ├── template.md     ← Claude가 채울 템플릿 (선택)
    ├── examples/       ← 예제 출력 (선택)
    └── scripts/        ← 실행 가능한 스크립트 (선택)

⚠️ SKILL.md의 description이 스킬 매칭의 핵심, 사용자의 입력과 description을 비교해서 자동으로 스킬을 선택한다.
```
- 스킬의 2단계 로딩 방식
    - 1단계 : 평소에는 스킬 이름과 description만 로드(항상 메모리에 상주, ~50-100바이트, 가볍고 빠르게 매칭)
    - 2단계 : 실제 호출 시 `SKILL.md` 본문 + 참고 파일 전체 로드(필요할 때만 온디맨드 로딩, 전체 지시사항 활성화)
    - 평소에는 가볍게, 사용할 때만 전체를 불러오는 구조
    - 자동 정리(컴팩션)시 전체 내용은 정리되고 설명만 남는다.

#### CLAUDE.md vs Skills vs MCP vs Sub-Agent 비교
| 비교 항목 | CLAUDE.md | Skills | MCP 도구 | Sub-Agent |
| --- | --- | --- | --- | --- |

## SKILL.md 작성법
```md
ex)
---
# 스킬의 고유 식별자, 슬래시 명령에도 사용됨
name: ppt-generator

# Claude가 '이 요청에 이 스킬이 맞겠다.'고 스스로 판단하는 핵심 필드, 품질이 매우 중요
description: "PPT 발표자료 자동 생성. 'PPT 만들어줘', '발표자료 작성', '슬라이드 제작' 요청 시 트리거."
---
# 실제 작업 절차와 출력 형식을 자유롭게 기술, 길이 제한 없음
## 목적
주제와 핵심 내용을 입력하면 PPT 발표자료를 자동 생성합니다.

## 절차
1. 발표 주제, 대상 청중, 발표 시간 확인
2. 목차 및 슬라이드 구성 설계
3. 각 슬라이드별 내용 작성
4. .pptx 파일로 출력

## 자체 검증 체크리스트
- [ ] 슬라이드 수가 적절한가?
- [ ] 핵심 메시지가 있는가?
- [ ] 시각 자료 지시사항이 포함되었는가?
```
- description 작성 팁
    - Bad : "문서를 생성하는 스킬" → 너무 추상적
    - Good : "PPT 발표자료 자동 생성. 'PPT 만들어줘', '발표자료 작성' 요청 시 트리거."
    - 핵심 기능이 첫 문장에, 사용자가 쓸 법한 표현 3개 이상 포함할 것
- 좋은 description의 3가지 조건
    - 1). 핵심 기능 첫 문장 → 핵심 기능이 첫 문장에 나와 있는가?
    - 2). 트리거 표현 3개+ → 사용자가 실제로 말할 법한 표현이 3개 이상인가?
    - 3). 차별화 → 비슷한 다른 스킬과 구별되는가?

## 스킬 만들기
- 방법1(수동) : `mkdir -p ~/.claude/skills/ppt-generator` → `SKILL.md` 작성
- 방법2(추천) : `skill-creator` 플러그인
    - `/install-plugin skill-creator` 설치 후 자연어로 <u>"PPT 발표자료를 자동 생성하는 스킬 만들어줘"</u>라고 말하면 자동 트리거
    - `skill-creator`는 description 최적화, frontmatter 설정, 지원 파일 구성까지 스킬 작성 모범 사례를 자동 적용해서 `SKILL.md`를 만들어준다.

## 스킬 저장 위치
| 위치 | 경로 | 적용 대상 |
| --- | --- | --- |
| Enterprise | 관리 설정, `<plugin>/skills/<name>/SKILL.md` | 조직의 모든 사용자, 플러그인으로 배포를 해서 해당 플러그인이 활성화된 곳에서 사용 |
| Personal | `~/.claude/skills/<name>/SKILL.md` | 내 모든 프로젝트 |
| Project | `.claude/skills/<name>/SKILL.md` | 해당 프로젝트만(Git 공유 가능) |

- 우선순위
    - Enterprise > Personal > Project
    - Plugin 스킬은 `plugin-name:skill-name`으로 네임스페이스가 분리되어 충돌 없음

## 번들 스킬(Claude Code built-in skill)
- Claude Code에서 제공하는 스킬들, 적재적소에 잘 활용하자
- `/batch` : 대규모 코드 변경을 병렬 에이전트로 처리
- `/simplify` : 코드 품질을 자동으로 검토
- `/debug` : 현재 세션 문제 진단
    - Claude Code 자체가 이상하게 동작할 때 쓰는 진단용 skill, 현재 세션의 디버그 로그를 읽고 원인을 찾는다.
    - 사용자 코드 디버깅용이 아니다.
    - ```md
        ex) 
        /debug
        /debug MCP 서버가 계속 연결이 안 돼
        /debug hook이 실행이 안 되는 것 같아
        ```
- `/loop` : 프롬프트나 슬래시 명령을 현재 세션 안에서 정해진 간격으로 계속 실행
```md
ex) 
/loop 5m /code-review          # 5분마다 /code-review 실행
/loop 10m 배포 상태 확인해줘     # 10분마다 이 프롬프트 실행
/loop 배포 끝날 때까지 지켜봐줘   # 간격 생략: Claude가 알아서 간격 조절```
