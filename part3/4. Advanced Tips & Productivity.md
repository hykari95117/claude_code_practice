# 고급 팁 & 생산성 극대화 (Advanced Tips & Productivity)

## 멀티 인스턴스 운영
- 터미널 탭 여러 개를 열고 각 탭에서 다른 Claude 인스턴스를 돌려라
- 탭 이름을 바꿔두면 한 눈에 관리 가능
```md
탭 1: "Feature-Auth" — 인증 기능 개발
탭 2: "Bug-Fix" — 버그 수정
탭 3: "Refactor" — 리팩토링
```
- 아래는 내가 claude한테 물어봄 내용
- Q. claude code에서 하나의 프로젝트에 대해 작업하고 있을 때 동일한 디렉토리 경로에서 터미널을 여러개 띄어서 작업해도돼? 작업이 충돌나거나 컨텍스트가 오염되지 않나 해서
- A. 가능하지만 몇 가지 알아둘 점이 있다.
    - 기본적으로 안전한 부분
        - 각 터미널의 claude 프로세스는 독립적인 대화/컨텍스트를 가진다. 한 터미널의 대화 내용이 다른 터미널로 섞이지 않는다.
        - Claude Code는 세션마다 별도로 동작하므로 컨텍스트 오염은 걱정할 필요 X
    - 조심해야할 부분 → 파일 시스템 충돌
        - 여러 세션이 같은 파일을 둥시에 수정하는 경우 문제 발생
        - git 작업(커밋, 브랜치 전환 등)을 여러 세션에서 동시에 하면 충돌 혹은 예기치 못한 상태 발생
        - 빌드/테스트를 동시에 돌리면 포트 충돌이나 lock 파일 문제 발생 가능
    - 권장 방법
        - 작업 영역 분리 → 세션마다 다른 파일/디렉토리/기능을 다루도록 한다.
        - 같은 파일을 건드려야 한다면 git worktree를 활용해 각 세션마다 별도 브랜치 + 별도 디렉토리를 쓰는게 가장 안전(물리적으로 다른 경로에서 작업함)

## Git Worktree로 병렬 작업
- 하나의 Git 저장소에서 여려 개의 작업 디렉토리를 만드는 기능
- commit history는 공유하면서 파일 시스템은 완전히 분리
```bash
# 수동 worktree
git worktree add ../project-feature-auth feature/auth

# Claude Code 네이티브 지원 (추천)
claude --worktree feature-auth
claude -w feature-auth

# Sub-Agent에서 격리
isolation: worktree  # 에이전트 설정에 추가
```
- `claude -w` 한 줄이면 worktree 생성 → branch checkout → session 시작까지 자동
- 변경 없으면 세션 종료 시 자동 정리

## 음성 입력 (/voice)
- `/voice`로 음성 입력 모드 활성화
- Push-to-talk (스페이스바) 방식이며 한국어 포함 20개 이상 언어 지원
- 복잡한 요구사항을 키보드 대비 빠르게 전달할 수 있다.

## MCP 대신 로컬 Bash 스크립트
- 간단한 작업은 MCP 대신 로컬 bash 스크립트가 훨씬 가볍다.
- MCP 연결 없이 바로 실행되고 컨텍스트 공간도 절약된다.
```bash
ex)
# scripts/check-db.sh
#!/bin/bash
psql -h localhost -U dev -d mydb -c "SELECT count(*) FROM users;"
# Claude에게 "check-db.sh 실행해"라고 하면 끝, MCP 연결 불필요
```
